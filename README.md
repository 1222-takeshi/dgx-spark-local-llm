# dgx-spark-local-llm

NVIDIA DGX Spark（GB10・128GB 統合メモリ）**1 台**で動かすローカル LLM の、評価結果・運用方針・再現用ハーネスをまとめるリポジトリ。

> 状態: 整備中（private）。公開前チェックリストは下記。

## 結論（2026-10-12 時点）

| モデル | 役割 | 基礎 | Tool Eval | 長文脈 | コーディング（思考なし / 16K思考） | 速度（1本 / 8本合計） |
|---|---|---|---|---|---|---|
| Ornith-1.5-35B-A3B | **常駐の既定**（T1） | 94.7% | 93 | 4/4 | 28 / 33 | 約 97 / 約 345 tok/s |
| Qwen3.8-27B | コーディング重視の T1 | 94.0% | 94 | 4/4 | 30 / 39（40K思考で 46） | 約 78〜123 / 約 322 |
| Gemma-4-26B-A4B | 思考なしの下書き（T2） | 52.7%※ | 93 | 32K・64K で 1/2 | 37 / 24 | 約 30 / 約 195 |
| Nemotron-3.5-Lightning 30B | 速い収集・整形（T2） | 81.3% | 88 | 4/4 | 29 / 25 | 約 94 / 約 290 |

※ 出力が上限で打ち切られた分を含む（誤答ではない）。27B の 46 は打切りだった 20 問を 40K 上限で再実行して足した値で、他モデルの 16K 上限とは条件が異なる。参考のクラウド: Sonnet 5.5 = 55、Haiku 5.5 = 54（コーディング 60 問）。

- **ローカルに T0（難問の司令塔）は置かない。** 難しい設計・難問はクラウドへ回す。
- 1 台に載せるのは 1 モデルだけ（メモリ）。空きメモリは総量の 15% 以上を残す。
- 詳細: [results/RESULTS.md](results/RESULTS.md)、運用方針: [docs/operations.md](docs/operations.md)

## 構成

| パス | 内容 |
|---|---|
| `results/` | 集計表（生データは含めない） |
| `docs/operations.md` | 同時 Agent 数の式、メモリ基準、モデル別の使い分け、落とし穴 |
| `docs/survey/` | 日付付きのサーベイ（出典リンクと確度つき） |
| `harness/` | 基礎（`basics/`）とコーディング（`code/`）の評価ハーネス |
| `scripts/spark/` | Spark 上のモデル起動スクリプト（イメージは digest 固定） |
| `CONTRIBUTING.md` | 役割・置くもの/置かないもの・変更手順・CI の方針 |

## 再現するときの注意

- 基礎ハーネス（`harness/basics/runner.mjs`）は、sparkDash の `server/collectors/qualitySuite.js`（問題生成と採点）に依存する。**このリポジトリには含めない**。自分の sparkDash を用意して `./server/collectors/` に置く。
- コーディングのデータ（LiveCodeBench の問題文・テスト）は含めない。`harness/code/prepare.py` と `manifest.json`（データセットのリビジョンとシード）から取得する。
- 評価はストリーミングで行う。非ストリーミングで 300 秒を超えると Node の fetch が切れる。
