# 運用方針（ローカル LLM を DGX Spark などで動かすとき）

体制は上と同じ（規模別の3段階、書き込みは1人、reviewer / explorer は read-only）。ただしローカルでは **同時に動かす Agent の数をメモリと推論サーバーの上限で絞る。** 役割の割り当ては、判断が難しい部分は強いモデル（クラウドの Opus 等）、機械的な調査・整形・下書きはローカルモデル、を既定にする。

同時 Agent 数 = 次の最小値。
1. サーバーの同時処理上限（SGLang / vLLM の `--max-running-requests`、llama.cpp の `--parallel` など）。
2. KV キャッシュの余力（KV プールの token 数 ÷ Agent あたりの想定コンテキスト長）。
3. 速度の下限（1 Agent あたりの decode が実用域を下回らない本数。下の実測を参照）。
4. メモリの余力。**空きメモリは総量の 15% 以上（128GB 機なら約 20GB 以上）を残す。** 下回ったら Agent を減らす。モデルの二重ロードや、別の大きいサーバーの同居は避ける。

KV を起動時に確保する方式（SGLang・vLLM）は、Agent を増やしてもメモリは増えず、増えるのは待ち時間と KV の奪い合い。スロットごとに確保する方式（llama.cpp・Ollama）は、Agent 数 × コンテキスト長 × KV 容量でメモリが増えるので、起動前に計算する。Agent 自身のプロセス（CLI）のメモリも見込む（目安 1GB / Agent）。

実測の目安（DGX Spark GB10・128GB 統合メモリ、Qwen3.8-27B NVFP4 + SGLang、`--mem-fraction-static 0.50`・`--max-running-requests 8`、2026-10-10）:

| 同時 Agent | 1本あたり decode | 合計 |
|---|---|---|
| 1 | 約 78〜123 tok/s | 約 78〜123 |
| 4 | 約 59 tok/s | 約 205 |
| 8 | 約 62〜67 tok/s | 約 322 |

- この構成の既定は **同時 4 本まで**、上限 8 本。モデル稼働中のメモリは約 71GB 使用 / 空き約 52GB。
- 入力が長いと prefill が重い（128K で最初の応答まで約 2 分）。長いコンテキストを使う Agent は同時に 1〜2 本に絞る。
- 別のモデルや構成に変えたら、上の表と上限を実測で書き直す。WSL（15GB 程度）では大きいモデルは載らないので、小さいモデルか Agent 1 本を前提にする。

モデル別の使い分け（Spark 1台で実測、2026-10-12。コーディングは LiveCodeBench 60問、上限付きで打ち切り込み。クラウドは Sonnet 55 / Haiku 54）:

| モデル | 役割 | 基礎 | Tool Eval | 長文脈 | コーディング（思考なし / 16K思考） | 速度（1本 / 8本合計） |
|---|---|---|---|---|---|---|
| Ornith-1.5-35B-A3B | **常駐の既定**（T1） | 94.7% | 93 | 4/4 | 28 / 33 | 約 97 / 約 345 tok/s |
| Qwen3.8-27B | コーディング重視の T1 | 94.0% | 94 | 4/4 | 30 / 39 | 約 78〜123 / 約 322 |
| Gemma-4-26B-A4B | 思考なしの下書き（T2） | 52.7%（長い推論で打ち切り） | 93 | 32K・64K で 1/2 | 37 / 24 | 約 30 / 約 195 |
| Nemotron-3.5-Lightning 30B | 速い収集・整形（T2） | 81.3% | 88 | 4/4（約16万トークン） | 29 / 25 | 約 94 / 約 290 |

- **ローカルに T0（難問の司令塔）は置かない。** どのモデルもコーディングはクラウド（55）に届かない。難しい設計・難問はクラウドの Opus / Sonnet に回す。
- 常駐は Ornith を既定にする（速く、長文脈と Tool Eval が安定）。コーディングを任せるときだけ 27B に切り替える。同時に載せるのは 1 モデルだけ（メモリ）。
- 思考ありは、上限に達すると本文が空になる（誤答ではなく打ち切り）。思考ありは上限を大きく取り、打ち切りを別集計する。
- Qwen3.8-Flash-Next（NVFP4、重み合計 124GB）は Spark 1台に載らない（起動中にホストが停止した）。再試行しない。
